# Comment Cleanup

Inputs: an authorized comment-cleanup scope and baseline source/build. Output: a reviewed diff and explicit source/output comparisons. This method grants no editing or publishing authority outside that scope.

1. Classify comments as tool directives, mistake-prevention guards, history/rationale, code narration, data-entry provenance or obsolete text. Preserve tool-required directives. Decide whether each guard expresses a security, privacy, platform or deliberate-behavior constraint that code alone cannot show. Recheck deletion candidates independently before broad removal.
2. Save a baseline build and explicit guard lists for each editing area. Shorten only while preserving conditions, polarity, cross-file dependencies and execution order. A requested line limit does not justify changing generated content embedded in template strings.
3. Compare JS/TS with comments removed using a syntax-aware method. Compare generated output separately. For long HTML, normalized comparisons that strip comments can be useful; state that they do not prove byte equality. Inspect template-string SVG comments as generated content.
4. Independently review the completed diff, not only the proposed deletion list. Compression can introduce new false statements or omit a condition. Check build-time values and CSS generated by source scanning; words in comments can generate utility classes. Confirm removed classes are unused before treating that difference as harmless.
5. Run the repository's applicable checks and report comparison scope and exclusions. Tests from an earlier small change do not validate a later broad cleanup.

## Inspect delivery thresholds and provider output

Measure generated delivery after shortening embedded asset comments. A smaller script can cross an inlining threshold and repeat on every page, losing cross-page caching. Compare first-page and later-page bytes separately. Also compare built HTML with served HTML before attributing a remaining comment to source; providers can inject markup.
