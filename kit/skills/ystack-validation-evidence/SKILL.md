# Validation Evidence

Inputs: the requested review scope or failed run, original acceptance contract, base source, proposed changes and permitted test environment. Output: a source-bound result with failures and incomplete gates visible. Keep author and independent reviewer separate. This workflow grants no extra access, observations, privileges or limit increases.

## Review repository findings

For a requested whole-repository review, combine focused review of recent changes with a fresh sweep from distinct angles. Have an independent skeptic reproduce proposed findings for each angle. Run completeness and deduplication passes. Keep owner-only actions, visitor-facing bugs, silent failure risks, cleanup and declined work distinct. Findings do not authorize implementation.

For approved fixes, reproduce the actual interaction in regressions, such as a real pinch-zoom gesture. Run every local CI step and report each result. Compare base and changed builds in focused reviews and a whole-diff review. Use before/after screenshots for visible changes. Report completed tests separately from pending independent reviews and screenshots.

## Establish the failure

- Preserve the failed run. Use one fixed regression on old code and the repair. Retain negative cases and cleanup assertions. Check required CI steps and actual result counts; tailed output is not a complete result. Compare CI configuration with the base branch so reduced coverage stays visible. Apply ordinary command permissions and risk-proportional verification.
- Bind hashes and coordinates to the actual final input. Transformed or nested scripts must not use transformed coordinates to validate original source. Missing exit codes or a failed evidence-collection stage cannot become a pass.
- For mode-based negative tests, read back the required mode immediately after chmod. An environment that never established that mode has an invalid fixture prerequisite; it has not proved a missing product rejection. Preserve the rejection rule.
- Finish fixture and diagnostic-file preparation before freezing file and parent-directory identities. Then prove real file and directory drift still fails before the protected call. Fixing a new setup failure does not resolve a historical incident automatically.
- Separate call-count instrumentation from timing of unwrapped functions. Compare real workloads on fresh equivalent state. Do not use artificial warm-up loops or cached-state advantages. If no measured benefit exists, do not claim an optimization fixes a timeout.

## Resume a bounded campaign

Use a compact, hash-identified handoff with the exact source, selected original receipts, current manager and old manager's stop condition. Read selected evidence before live Git/CI/claim/worktree checks. Do not treat aggregate state as current or scan all old state by default. Record consumed and remaining windows, resource caps, stage order, stop conditions and unresolved operator decisions. Carry forward only documented in-scope authority; preserve uncertain filesystem state and explicit cleanup prohibitions.

Rebind every actual execution consumer and path, not only cwd or an outer launcher. Check schema at each consumer: nested fields do not satisfy top-level requirements. Reproduce the original failure, accept the smallest repair and retain missing/wrong-field negatives.

After failure, stop the acceptance chain. Diagnose, repair minimally, and independently review source and the affected regression recipe before another authorized full window. Source or base changes need fresh review and GO. Ordinary controls cannot replace full owner-flow runs or refund consumed windows.

## Revise construction order within approved scope

For an authorized order change, keep implementation frozen while revising the specification and then its bound plan separately. Distinguish permission to write inactive downstream source from acceptance of that source. Preserve prerequisite acceptance, scope, budget, tests, historical failures, capacity debt and final merge obligations. Keep independent review and required artifact CI; artifact CI does not establish implementation coverage.

Merge the accepted base normally into the original source branch and compare source/test bytes. Before resumption, check real interfaces and ownership, fresh claims and the exact required GO. Missing real interfaces block dependent code; do not substitute fake data. Complete assembly and staging still need real interfaces, a frozen candidate and renewed review. Reuse unchanged proof only after verifying source binding, without rerunning old execution windows. Resolve symbolic plan paths to their fixed generation before comparing the full source/adoption inventory; retain failed checks.

## Bound independent-review retries

Apply only where the existing review contract permits a retry. Separate invalid reviewer output and transient timeout/network/service failures from valid content rejection. Permit at most one fresh independent read-only review with the same model, bound to unchanged HEAD, full index and supplied evidence hashes. Do not retry valid content rejection, authentication, configuration or local I/O failure.

Validate every returned finding independently, including findings after malformed entries. Carry all validated findings into the final result; neither response order nor a later empty result may erase them. A second failed attempt is not approval: preserve the candidate and stop. Keep privacy, information-preservation, encryption, commit and progress gates unchanged. Plaintext diagnostics contain only fixed failure categories and fixed validation reasons, never private quotations or raw model output.

## Check fragile regression recipes

- Directory link count can change after legitimate file creation. Adjust identity creation and checks together while keeping device, inode, type/mode, owner/group checks, report hard-link and permission negatives, and a real directory-replacement negative.
- If process-group polling reaches the existing deadline, a nonblocking child wait can still reap without extending it. Unknown group state still fails closure. Retain thread, FD, wait and metadata-restoration evidence.
- If a real fixture never acquired setuid, use controlled metadata only when the original test contract permits it. Preserve actual and injected values and the original refusal location. Test writable source, controlled setuid and later mode drift separately; never claim a real kernel setuid state was proved.
- For code generation, replace a unique complete template slot. A global CALL replacement can corrupt NOT_CALLED. Compile the complete original broken output and exercise the repaired generator plus inverse transform through the original chain. Preserve original payloads and collision-bearing inputs. Preparation is distinct from worker execution or full validation.
- Capacity is a separate gate. Verify how every real consumer reads reused immutable inputs and account for every new physical output. Keep masks, faults, interleavings and thread/FD/write evidence. If one sub-budget is too small, rebalance within the unchanged total without dropping outputs or assertions. New controls cannot replace unknown historical closure or physical-write facts. A higher total cap needs its own approval.

## Preserve failure evidence

Before implementing an export repair, resolve its retention and disclosure contract.

- An early cap rejection can bypass export of bytes and stage records already in memory. Preserve only already-read bytes within the authorized boundary; add no reads. One read may cross the cap, so retaining all captured bytes can conflict with the retention allowance. Resolve that conflict explicitly; increasing the cap alone does not fix lost evidence.
- Cover every sampling stage, including Git. Preserve the primary error if export also fails, and propagate the original cancellation signal. Establish metadata-writer closure before calling records complete. Set any required unclosed-target stop marker before optional export so interruption cannot bypass the stop state.
- Identify the actual destination and readership. A private review or code boundary does not make records in public CI logs private. Retention scope grants neither disclosure nor recovery authority.

## Account for a preflight rejection

After rejection in a bounded validation run, independently check whether any real execution phase or restricted query started. Preserve the rejection, invalid execution record and accounting evidence. Correct the record's binding to the accepted claim. Recheck all existing limits before deciding whether the original authorized run remains unused. Failure alone does not mean unused authorization. This check grants no retry or budget reset.

Reconcile sampling starts from the complete relevant dispatch set and actual execution evidence. Separate local ordinary controls from qualifying platform starts. If missing receipts support only a range, preserve that range; do not turn uncertainty into unused attempts. A new validation window does not reset a separate sampling allowance. If a log connector fails, existing authorized access may retrieve the same completed job's full log; preserve the connector error and verify the saved length and hash. Terminal runner status does not prove restoration or process closure. Keep attempt use, primary failure and restoration evidence separate.

## Validate evidence compaction

- Deduplicate only byte-identical payloads. Retain references sufficient to reconstruct original bytes, ordering, identities, timestamps and fields. Keep original encoding and serialization; normalization is not lossless reconstruction.
- Inventory every artifact in the agreed accounting contract: generated source, temporary/native preparation files, archives, final indexes and output. Bind accounting to each actual write. An old identical-content record does not account for a new write. Preserve required overwrites and clears.
- Use existing captured bytes; do not add observations to conceal accounting gaps.
- Test full reconstruction, continuing-writer isolation between reports, malformed references and encodings, failed writes and unchanged state after failure.
- For cost-threshold regressions, choose a fixture where old undercounting wrongly selects a shared representation and the corrected calculation retains full text. A new-value assertion alone does not establish the regression.

## Bind derived inputs and protocol checks

- After metadata-only rebinding, check every decision-package digest, source blob, artifact chain, role and output index. Preserve overwritten bytes and their write costs. Verify allowed changes and the full independent review. Approval and static acceptance do not issue GO; the designated operator must create and read back the claim and every consumer field.
- After a late-stage assertion failure, inspect downstream derived relationships before another bounded execution. Bind current generated setup, permit only approved source differences, check every drift-test location, and compare formal and ordinary hashes separately. Do not weaken the relationships protected by assertions.
- Reproduce old failures and require rejection of missing, duplicate and unapproved content, with the failing node identifiable. An extracted helper may need imports such as `ast` in its execution namespace. Generated drivers/workers/channels may be limited to byte and syntax checks; do not execute them when outside the recipe.
- Reuse static checks only with original receipts and byte-identical inputs. Check changed source still in use and items missing receipts. Freeze the final index and hashes after revisions, then independently review those exact inputs.
- For a protocol declaration omission, trace the rejected record to the bound producer. Adding keys alone is insufficient: validate structure, provenance, occurrence count and correspondence with the success result. Require strict JSON types even when values compare equal, and explicit ordering within the same success. Keep malformed-type/order regression cases and the first failed validator revision. Review the repair and ordinary recipe before execution.

For a protocol-count repair, compare the original assertion with complete saved producer output. Where the recipe permits, extracted AST checks can consume saved JSON and source bytes without reading old owned paths or running the complete tail. Pair old-value rejection with new-value success and corrupted-reference negatives. Verify actual exception types and refusal locations before execution. Check extracted methods are bound to test objects so setup does not fail before the intended path. Withdraw findings disproved by source, retain the correction, and leave correct implementation unchanged. Static recipe acceptance is not runtime coverage; report an unenforced deadline as a limitation.

## Budget execution and closure

- Measure complete saved raw output, including appended ledgers, separately from total physical writes. A small displayed summary does not eliminate a saved ledger or its downstream copies. Compare lossless producer/decoder changes with a bounded resource adjustment; projections do not establish measured capacity or permission to raise limits.
- Model raw growth through every downstream copy and final sealing, including producer original writes and preservation of replaced roles. A raw cap alone does not establish sufficient total allowance. Separate fixed success-path estimates, worst-case bounds and measured costs. A failed run gives a lower bound; do not spend a bounded attempt on a projection already known to be insufficient.
- Charge accidental overcollection, failed and duplicate transfers, full exception chains and cross-directory preparation/reconstruction. Resolve overlapping ordinary and sampler costs explicitly. Use exact tool/transport byte intervals when recoverable; otherwise cover complete truncated sources and encoding layers conservatively. Preserve actual review, GO and closure reserves rather than cutting required output. Retain rejected budget packages. For a resource-only revision, review changed numbers and forward bindings against unchanged contracts, recovery scope and gates; do not repeat accepted unchanged technical reviews.
- Charge original invocation metadata before overwrite, every replacement, and each archive copy. Distinguish regular files and symlinks. Retain preparation-source versions and complete failures to establish whether failure occurred before the first package write or candidate execution. Keep producer-ledger totals, directory size and later ledger copies separate; none substitutes for complete historical accounting.
- Reserve for source, fixtures, JSON escaping, duplicate copies, reviews, tool records, readback and final sealing. Charge failed sealing attempts and refresh complete cost. Passing tests or an accepted producer ledger do not establish package capacity. Keep sealed accounts immutable; charge later preparation to its own account and bind accepted results without rerunning unchanged tests just for metadata.
- Budget through claim/GO creation. A startup hard-gate rejection before those writes must remain visible. Independently review any internal reserve reallocation within the unchanged total, preserving raw-output and later-execution reserves and all evidence requirements. Retain separate per-source caps even when an overall window grows. Reallocation is an engineering projection, not capacity PASS.
- Where display truncation prevents exact recovery, retain the limitation and substantiate a conservative finite accounting upper bound. Never charge zero or label a guessed bound verified.
- Wait for terminal output and both complete streams and outer handles to close before the next stage. Do not read a raw file while its producer writes it. Historical closure follows the original contract's actual registered subtasks, foreground processes and pipelines; do not silently add internal descendants as acceptance gates.
- Preserve accepted component accounting and executed-prefix closure even when resource or late-stage failure defeats full acceptance. Neither partial pass nor ordinary regression completes missing stages or the final sealer, erases failures/UNKNOWN totals, refunds attempts or restores an exhausted allowance.

## Check fixed publication bytes

For an already authorized fixed publication, compare the complete readback with the approved file by length and hash, including the terminal newline. Preserve an incorrect publication, failed check and inaccurate verification claim. A correction to the same publication needs applicable authorization; a one-byte restoration is not general editing permission. Distinguish that correction from a second publication.

## Close the result

To close a historical failure, connect its original failure path to the current repair by comparing the relevant evaluator and changed code. A fresh green run alone does not establish causality. If neither affects that path, retain the unresolved gate; this review grants no diagnostic execution permission.

Rebind after source changes and rerun affected validation. Distinguish local controls from full required platform acceptance. A prior green result cannot approve new source. Report completed and remaining gates separately.

## Source-bound capacity and integration checks

Apply these checks when the acceptance contract requires a complete bounded evidence package. They do not add a new proof requirement to ordinary tasks.

- Compare a demanded investigative method with the original contract. Remove an unsupported requirement to prove every runtime implementation when the contract requires only a complete fixed-path cost proof. Preserve actual retention, capacity and closure obligations. Upstream runtime source alone does not establish a vendor-modified runtime's behavior; record applicability conditions.
- Before promoting controlled results to CI, check repository assertions, fingerprints and actual regression wiring together. A passing extracted recipe can coexist with stale repository assertions or omitted tests. Resolve a line-limit conflict through the applicable plan process; do not remove required coverage. Avoid running an extra isolated batch when the original required entry points already run all controls once.
- Select generated-code call sites by source position and nesting level. A textual replacement can hit an embedded close operation and miss the outer call. Check each real call, OS-call counts, embedded source, protected function bytes, lifecycle records and forward/reverse reconstruction. Refresh every affected source binding before reusing capacity proofs. Preserve old derivations and issue forward corrections. Acceptance of an exact-path expansion does not validate a faulty general path formula; inspect suspected omissions before charging them. Check fixed source line numbers, class-method inventories, selector lengths and failure-result counts after controls change.
- Bind environment and executable identity at preparation, execution and sealing entry points, not only inside the final driver. Preserve actual configuration-selection semantics; do not derive HOME or config directories from guessed paths. Inspect active commands separately from inert fragments. Bind necessary existing environment values without recording secrets. Match bounds involving generated syntax to the actual generator runtime.
- Derive bounds from exact serialized producers, path sources, replacement multiplicity, write sites and full copy chains. Include newlines, JSON indentation, escaped Unicode (a surrogate-pair escape can take 12 bytes), nested encoding, stack frames from comprehensions, exception chains from waits and closing, and complete malformed-input arguments. Fixed successful widths do not bound every failure. Inspect existing reachable input constraints before adding guards or arbitrary constants. Keep unsupported widths as explicit parameters rather than zero. Use an existing pre-decode hard limit to bound newly added log-line fields without rereading large logs. Separate source-provable quantities from quantities needing frozen log intervals; freeze all relevant streams together at final packaging.
- Follow SDK type aliases through their complete chain, then verify language-level field mapping and conversions separately. A local observed username or stat value is only conditional evidence. Bound context count by actual write count when the source establishes that relationship, removing only a redundant independent context-count limit. Keep complete filenames, malformed input and failure copies charged. Trace exception names at the selected call sites. Source inspection of FileIO.close must include its RawIOBase.close/iobase.c path before claiming complete close-chain bounds.
- Trace subprocess-start and pre-return preparation failures. Retaining only exception class and frames can lose original text; saving child output only on normal return leaves exceptional paths uncovered. Avoid success summaries after failure and recursive attempts to rewrite a failed receipt. More capacity does not repair missing evidence.
- Compare an individual member cap only with costs assigned by the actual sharing contract. A mandatory unsplittable success record can establish a lower bound above that cap even when the aggregate allowance is larger. This proves insufficiency, not a sufficient replacement allowance. Accepted component subtotals exclude unreviewed owner output, transport and closure.
- Distinguish two witnesses of one write from two physical writes. Count each persistent save, complete readback, split-line content copy, transport and final duplicate independently. File counts and print counts do not bound complete content copies. Reconcile historical overwrites and all relevant tool results; directory size is not historical cost. Replace only the measured execution reserve, without subtracting costs twice or dropping unrelated reserves.
- Include full relevant logs, including prefixes and dynamically added review artifacts. A fixed validator can read complete retained receipts and return bounded summaries plus hashes; retain originals. Summary-only inspection is not validation. Treat internal suballocations as gates too. Reconcile already-charged copies before revising allocations within an approved total; freeze the changed bindings and independently review affected reserves. Preserve the applicable treatment of private reasoning and context rather than inventing one. Keep final readback, review rewrites and sealing costs in the prediction. Check costs before each supplemental acquisition; a larger allowance does not reset prior costs. Stop under the actual package rules and preserve an overrun when proposing an increase.
- Verify an idle reviewer actually receives a new turn; message delivery alone need not restart it. Check model-discrepancy claims against original logs, preserving the retraction when a summary was wrong. Logged model configuration is not proof of invisible backend identity.
- Recheck an approved fixed announcement's factual source binding immediately before publication. If it is stale, retain its approved bytes and publication count and defer it; do not silently edit or publish stale text. Other authorized preparation may continue.

## Lossless short-write and failure records

- Separate bytes actually written, temporary memory and retained failure evidence. Successful short writes need not output every remaining suffix. Establish shim installation time, path intersection, loop and state-update order before assigning a quadratic bound. A failure before write-depth updates can duplicate suffix evidence even when the OS write occurred once. Preserve a withdrawn false diagnosis separately from a remaining conditional counterexample.
- Include metadata amplification from tiny writes. Neither an unproved one-byte pattern nor an unsupported tighter event count is a measured result. Compare any representation change with the parent specification before implementation.
- Preserve the complete legacy accounting view and fine-grained view on encoding failure. UNKNOWN plus partial evidence is insufficient when the contract requires full retention. Keep event order, identities, zero-write/error paths and separate report slices. Equal legacy values do not justify replacing a decoded subrecord with a global record; preserve its object identity and test that case.
- Separate shared backing, logical frames and original input identity. Share only after full byte equality; retain invocation input and offsets and fall back to full original data on mismatch. Keep failure references locally scoped; reject one original object ID mapping to different complete bytes across tables. Preserve copied encoded values if the original decoder fails. Pool/span storage can reduce wire duplication without removing suffix memory or expanded recovery costs. Do not infer globally linear growth. Check the actual emission branch. Treat a conditional derivation as distinct from an observed overrun.
- Require correct declaration-table types and reject unused declarations without rejecting legal zero-write/error references. Do not let legacy JSON tolerance swallow new decoder failures. Test negative cases, clear/overwrite behavior, continuing-writer isolation, sampler forwarding, zero writes, error after a prefix, FD reuse and actual failure-data reconstruction. Reuse existing phases and in-memory inputs only where the recipe permits; charge their costs.
- Keep original assertions or redirect them to equivalent full logical-frame checks. Freeze one complete repair from the original author, including all findings, and independently review its integration. Static source, recipe, wiring, full capacity and execution are separate gates.

## Additional evidence and limitations

- A static reconstruction does not replace the required actual preparation proof before public source publication. Fast CI alone does not close review or the full matrix.
- A closure projection that exceeds a sub-budget does not prove that actual writes already exceeded that cap.

## Reachability and accounting refinements

- Bound fields that can coexist at the actual serialization point. A union of possible fields can overcount mutually exclusive or post-write fields. Trace preceding guards before calling an overflow reachable. Inventory multiline child stdout, groups in stderr and error branches alongside single-line adapter output.
- Bind numeric widths to the platform domain and actual formatter entry, including format code, precision and flags. Do not substitute a generic float-width assumption. Do not assume a fixed groups count from an obsolete platform limit; keep an unresolved bound explicit.
- When the contract permits in-memory-only restoration, expanded memory does not itself consume a physical-output allowance. Charge actual writes and transport copies separately. This distinction does not prove sufficient capacity.
- Bind serialization counts to the complete current call graph before applying byte bounds. Inner-call metadata can be wrong even when the resulting count is unchanged. Issue minimal forward corrections; accepted call counts do not establish complete byte capacity.
- Successful source GETs do not establish acquisition-cost compliance. Include command transport, reads, writes and required raw-evidence sealing in the stop gate. Stop new acquisition when that gate fails, preserve already-returned complete evidence and charge actual overruns. Conditional source conclusions can remain valid within their conditions despite separate cost failure.

## Capacity and provenance refinements

- Prove producer-operation bounds before detailed serialization accounting. A collector that saves complete output before checking its size has no pre-write bound. Any repair must retain complete records and prove ownership and cleanup of partially constructed processes after budget exhaustion.
- Bind every copy to its writer, runtime instance and output branch. Charge physical saves and transmissions under the actual contract; in-memory growth is a separate property. Include stale state, nullable fields, repeated failure appends, directory-FD lifecycles and cleanup after report output. Recompute generated-source lengths after guards, appends or substitutions change.
- Bind historical policy to the producer’s actual saved bytes, preserving legacy compatibility separately. Exercise real producers and readers, valid controls and paired attacks. Recompute content digests rather than compare declarations alone.
- For two-source consumers, release all held resources, including recursive prerequisites, before the second source. Reauthenticate and own final resources before the completion marker. Test nested channel lifetime with a real subprocess, directory persistence, cleanup failure, conflicting inputs and marker absence on failure. Do not convert a source failure into valid stale evidence.
- Keep complete CI results by exact source revision. Where existing CI provides the required pinned tools, inspect every required suite’s full logs. Pure-data or mechanism passes do not establish native execution, distinct real principals or final acceptance. Preserve NOT RUN tests and later failures separately from earlier passes.

## Validate replay and admission changes

- Extract deterministic calculations for both production and offline callers while leaving real I/O and privileged operations in the original entry points. Preserve build wiring. Trace each captured field into the actual calculation; a read alone does not prove use. Validate captured data through the existing reader, retain required format compatibility, and rerun pairing after source changes. Include narrow mutation and deleted-call controls.
- Bind replay to runtime responses and startup PID/error as well as inputs. Preserve PID matching, timeouts, termination confirmation and full byte comparison. A preserved production exception may justify replay rejection only under the original contract; rejection cannot replace successful real trials. Fresh nonces and live-store reads can defeat a claimed deterministic recipe.
- Reconcile recording limits with the consumer's full input. Preserve original output, result and cleanup even when a record is ineligible for replay. Resolve an insufficient cap through the existing contract process. Count every real full-export read, repeated hash, comparison and final verification; exclude only copies never made, while retaining actual copies and failures.
- For nested integrity, calculate a digest from held content and compare it with the declaration. Preserve shape errors. Pair changed-content/old-digest rejection with recomputed-digest recovery through the real entry point. Bind historical plans to their original bytes after legitimate later updates.
- Inspect the actual packaging selector before preparing an inactive version. Separate specified core work from undefined transport work. Include shared helpers in each dependent test-package copy. If admission validates a draft before final construction, use the original constructor and check the final fields against the admitted fields; prove rejection prevents subprocess startup.
- Verify inherited source against original review receipts and the complete provenance inventory before adoption. Review the actual merge separately, including both sides' test logic. Adoption within existing scope does not close dependency acceptance or enable release.
- Freeze finite test inventories and trace each case to its target call. Compile embedded injected code separately from shell syntax checks. Localize helper variables that overlap caller bookkeeping. Make negative fixtures pass earlier prerequisites, retain loader permission checks, and distinguish executable gated cases from NOTRUN placeholders. Reconcile nested counts without counting included paths twice. Preserve detailed receipts before cleanup only through an authorized disclosure channel.
- For additive checkout repairs, subtract additions and compare the remaining workflow bytes with the original. Verify authentication configuration removal before tests in full job logs. Preserve strict provenance rejection and separate policy-digest failures. Stabilize the base within existing coordination authority, review the resulting head, and reconcile its complete original test inventory, exits and genuine skips. Older-head passes do not approve newer source.

## Recording and cleanup review

- Inspect protocol-version read traces, including bytes consumed before rejection. A new frame allowance must not silently enlarge old-version consumption. Test formats do not establish production protocol semantics.
- Trace complete bytes across process boundaries; digests cannot substitute for data needed for replay. Enumerate physical copies, write scope and costs before accepting a revised interface. Retain bytes at their original read points where the contract permits, preserving native behavior and first-error precedence.
- Test the real cleanup sequence after copying. Separate retained data from native temporary cleanup without deleting required originals. Require successful closure of added recording handles before completion. Marker existence alone cannot prove producer success; bind cross-process failure and close-time accounting failures into the final sealing decision. Terminal-state records must retain actual post-write observations and incurred costs; terminal codes alone do not meet that obligation.
- Check failures after acquisition but before bookkeeping, and paired cancellations during cleanup/tail accounting. Preserve the first failure. Carry costs by operation/case and keep absent cross-process charges UNKNOWN. Keep fixture-specific ceilings separate from production limits.
- When a moving CI image accompanies a failure, verify whether the contract requires that image before proposing a baseline pin. Retain tests and failed evidence, independently review the exact candidate and run its complete required inventory. Check loader fixtures preserve authenticated identity and negative tests reach the intended integrity check.

Use these checks when a change transfers live file ownership or accounting between existing callers. Keep the original contract's permissions and native behavior.

- Cover acquisition through owner construction and registration. A successful duplicate followed by failed allocation can leak; cancellation after registration but before clearing a pending reference can double-close. Keep one cleanup owner throughout. Exercise compensation failures and preserve the exact first cancellation object, including when callers use different cancellation markers. Check each receiving caller registers, rechecks and closes its holder exactly once.
- Retain observations at the original read point. Bind copied holders to actual stat/hash/readback results and independently owned authenticated parent chains. Preserve original close points; do not reopen historical paths. Return an owner only after required accounting and receipt handling succeeds. On failure, close the new resources and retain incomplete state and incurred costs.
- Exercise the complete production sequence. Controlled creation may update only the permitted directory metadata; retain file and ancestor drift checks. A live directory may require the original full inspection again. A held copy cannot replace original live custody. Observe the original close call's return or exception; an emptied collection or terminal state does not prove closure.
- Compare the entire readback, including extra trailing bytes. Confirm a negative fixture reaches the intended check. Preserve injected faults and unrelated assertions when repairing mixed positive/negative tests; add a separate clean positive. Keep inventory and command-receipt filenames distinct. Check modes as well as content, and do not label regenerated evidence recovery of the lost original.
- Build role inventories from actual held objects and copy events before each owner closes. Preserve producer representation and request schemas. Explicitly bind occurrences across launches. A bijection over present members is only a partial inventory; reject missing required roles. Recompute results from real inputs and generated outputs, reserving recorded results for the final comparison.
- Carry failed-stage and close-time increments through the original case, common and window ledgers. Preserve provenance categories with an independent binding. Overlapping views are not additive charges. Use transfer watermarks; a new zero leaf cannot erase caller costs. Unknown attribution remains UNKNOWN. Preserve first error and partial transfer state; do not automatically repeat a partly failed transfer.
- Enforce the existing case and window limits before writes. Pass actual carry and reservations to the existing chunk-budget owner, preserving old defaults and formulas. Consume cleanup costs from their existing reservation rather than reserving them again. Distinguish pipe writes from disk occupancy. Pair old/new small-cap boundary controls; a large-cap counter test does not prove large physical writes or full capacity.
- Review original argv, environment, streams, signals and error order through the entire launcher lifecycle. Added evidence-retention failure must preserve native error and cancellation behavior under the governing contract. Successful transport does not establish underlying write count or accounting-process closure. Preserve channel admission and failure retention separately.
- Reuse old proof only after checking changed transitive dependencies and applicable input branches. A later checkpoint cannot replace missing pre-execution source binding. Targeted early review does not replace final review. Necessary launcher or size changes still follow existing specification and plan gates; retain required tests and do not treat specification acceptance as implementation authority.

## Check replay input and settlement boundaries

- Preserve getter and failure order when extracting shared calculations; byte-equivalence controls alone cannot establish it. Distinguish authenticated external inputs from derived outputs by causal owner and occurrence. Preserve missing observations as missing, not verified absence.
- Keep observations, semantic bindings and physical copies distinct. Reuse a retained entry only when its complete source identity, path and bytes still match. Retain original authentication and processing costs. Equal hashes alone cannot merge independent holdings or projections.
- Test actual owner-binding checks without mocking them away. Distinguish equal bytes, file identity and object identity; legitimate independent holders need not be the same object. Finish independent copying before original closure. Chunking does not bound memory when all chunks remain retained, and in-process retention does not establish subprocess custody.
- Freeze actual authors before bounded shared-checkout controls, stop on the first failure or timeout, and verify source bindings afterward. If a fixture fails before its target check, repair its prerequisite or projection without weakening production validation. Run affected and unexecuted controls without repeating already-passed unchanged groups; keep earlier failures and source-freeze defects visible.
- Live subprocess budgets require both finite non-overlapping reservations and settlement of original receipts, failure costs and closure tails. Authenticate operation, actor, process and scope; totals alone do not prove ownership. Keep distinct original receipts separate and missing evidence UNKNOWN. Verify body allowance before data writes and closing allowance only in the closing phase.

## Check acquisition carriers and collector fixtures

- Bind transported bytes and their inventory to the same original acquisition through each projection and the real parent consumer. A complete manifest cannot replace missing candidate-file bytes. Enumerate the complete member scope and uncertain costs before proposing transport beyond a fixed interface.
- Before adding a clock snapshot, check the required owner and interval against existing captures. Records added later for another owner do not invalidate an adequate earlier snapshot. Keep new accounting checks inside the original native control-frame error-isolation boundary.
- Preserve original version checks and necessary tool copies inside authorized scratch. Keep separate activities' execution and high-risk plan permissions distinct. Read complete receipts and compare source/tool bindings before and after bounded controls.
- Exercise ownership checks through the actual consumer with a valid session. Distinguish parent coverage from the inner owner. Pair a correct-owner positive with wrong Reader, session, source and cross-request negatives.
- Count product drain closes separately from fixture fallback closes. Retire owned children on cancellation; do not retry a descriptor operation whose state is uncertain. Verify exception types against the actual runtime API while retaining the original failure.
- For hermetic collector tests, establish network denial in every fresh interpreter. Startup rejection does not prove isolation. A body-cancellation control must reach the body phase. Check IPC byte limits, deep validation, trailing HTTP bytes, test side effects and closure after expiry.
